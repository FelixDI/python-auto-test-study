# Jmeter
```
正式性能测试，重点 Aggregate Report 聚合报告
主要观察三个核心指标：95% 分位响应时间、吞吐量、错误率。
平均耗时只能做辅助参考，95% Line 才能客观反映绝大多数用户的访问体验。
当并发不断加大，一旦 95% 延迟陡增或者错误率上升，就找到了系统的性能瓶颈拐点。

Python性能测试框架Locust优势明显
# 进入性能测试目录
cd performance/

# 启动 Locust Web UI   http://127.0.0.1:8089
locust -f locustfile_httpbingo.py

# 无头模式
mkdir -p ./reports
locust -f locustfile_httpbingo.py \
--headless -u 50 -r 5 -t 120s \
--html=./reports/locust_httpbingo_$(date +%Y%m%d_%H%M%S)_u{u}_r{r}_t{t}.html

子进程调用 locust 命令，导出 CSV 后读取数据写入 allure报告
```

# 禅道/Jira  报bug
```
【bug标题】创建订单时允许负数数量，导致库存无限增加
【严重程度】致命
【复现步骤】
1. 创建一个库存为100的商品
2. 调用创建订单接口，传入quantity=-1
3. 查询该商品的库存
【预期结果】
- 订单创建失败，返回422错误
- 商品库存保持100不变
【实际结果】
- 订单创建成功，返回200
- 商品库存变为101
【影响范围】
用户可以通过购买负数数量的商品，无限刷库存，严重影响业务逻辑
```

```

## Jenkins容器 集成UI测试 
```
Jenkins 容器默认只有 Java 和最小化系统库，
运行 Chromium 所需的图形、音频、字体等底层库全部缺失.

无头浏览器的系统级依赖,安装系统依赖
docker exec -it -u root jenkins bash -c "
  apt-get update && 
  apt-get install -y libgtk-3-0 libnotify4 libnss3 libxss1 libxtst6 xdg-utils libatspi2.0-0 libsecret-1-0 libasound2 libgbm1 libxfixes3
"

行业里的标准做法是通过定制镜像或 CI 脚本，让 Jenkins 环境能做到“开箱即用”。
通过一个自定义的 Dockerfile，构建一个包含 Jenkins + Python + Playwright
 及其所有依赖的定制镜像，从而彻底解决每次构建都要安装环境的问题。
```
```
CI/CD

     └── Workflow(yml)

requirements.txt 包含的插件 最好写固定版本
