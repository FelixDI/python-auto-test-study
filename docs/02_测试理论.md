# 一、软件测试理论基础
（建立标准化测试思维，理解 "为什么测" 和 "怎么测"）

## 软件测试的定义与原则
定义：在规定条件下运行程序，发现缺陷、评估质量

七大原则：测试证明缺陷存在，但不能证明不存在；穷尽测试是不可能的；测试尽早介入；缺陷集群效应（二八定律）；
杀虫剂悖论（定期更新测试用例）；测试存在依赖性，不同测试侧重点不同（功能、性能、安全、兼容性）；不存在无缺陷的软件。

## 软件测试流程
需求分析、测试计划、用例设计、测试执行、缺陷管理、测试报告（重点：敏捷开发下的测试流程Scrum）

## 测试类型分类
按阶段分类：单元测试、集成测试、系统测试、验收测试

按方法分类：黑盒测试（功能）、白盒测试（代码）、灰盒测试（接口）

按内容分类：功能测试、性能测试、安全性测试、兼容性测试

## 测试用例设计方法
等价类划分（接口测试核心）

边界值分析（最容易发现缺陷）

场景法（业务流程测试）

错误推测法（UI测试常用）

## 缺陷管理
缺陷生命周期：New→Open→Fixed→Verify→Close/Reopen

缺陷报告要素：标题、步骤、预期结果、实际结果、截图/日志

# 二、自动化测试概述
（理解自动化测试的价值、适用场景和技术选型）

## 自动化测试定义
用代码/工具替代人工执行测试用例，自动验证结果并生成报告

## 自动化测试优缺点
优点：提升回归测试效率、保证一致性、支持夜间执行

缺点：开发维护成本高、不能完全替代手工测试

## 自动化测试适用场景
适合：稳定功能的回归测试、大量重复操作、数据驱动测试

不适合：界面频繁变动、一次性功能、需要主观判断的场景

## 测试金字塔理论：

核心：底层多、上层少
1. 单元测试（70%）：开发自测
2. 接口测试（20%）：自动化测试核心
3. UI 测试（10%）：仅覆盖核心流程

```
        /\
       /  \
      / UI \          ← Selenium / Playwright
     /------\
    / 服务层 \        ← requests / pytest
   /----------\
  /   单元层   \      ← unittest / pytest
 /--------------\

```

## 自动化测试ROI分析
投资回报率：节省的人工时间/自动化脚本开发维护时间

原则：优先自动化高ROI用例（如登录、下单等核心流程）

## 自动化测试工具
Postman：日常调接口、功能测试、写接口文档（轻量、人人用）
JMeter：专门做接口压力 / 性能测试（重型、专业测试用）
