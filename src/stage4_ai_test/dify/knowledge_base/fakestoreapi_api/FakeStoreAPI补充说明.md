# FakeStoreAPI 补充说明文档
## 一、基础全局信息
1. 接口基础地址（根域名）：`https://fakestoreapi.com`
2. 协议与格式：全接口 HTTPS 协议，请求与响应数据格式统一为 JSON
3. API 版本：v2.1.11，当前为公开稳定版本

## 二、鉴权规则说明
1. **全接口无强制鉴权**：商品、购物车、用户模块的所有CRUD接口，调用时无需携带任何身份凭证（Token、API Key、Cookie均不需要），直接请求即可返回数据
2. 登录接口 `/auth/login` 为模拟接口：
   - 传入符合格式的用户名密码会返回模拟 JWT Token
   - 该 Token 仅用于学习鉴权逻辑，**调用其他接口时无需携带**，后台不做权限校验
3. 无接口调用频率限制，适合测试学习使用

## 三、接口设计规范
本 API 严格遵循 RESTful 设计风格：
1. 资源命名：接口路径均使用名词复数形式（products / carts / users），代表一类资源
2. 操作语义通过 HTTP 方法区分：
   - GET：查询资源，不修改数据
   - POST：新增资源
   - PUT：全量更新指定 ID 的资源
   - DELETE：删除指定 ID 的资源
3. 路径参数：`/products/{id}` 中的 `{id}` 为资源唯一标识，整数类型，用于定位单个资源
4. 响应码语义：
   - 200：查询、更新、删除操作成功
   - 201：新增资源成功
   - 400：请求参数格式错误、参数缺失

## 四、数据特性说明
1. 所有数据为模拟静态数据，不支持真实持久化：
   - 调用新增（POST）、更新（PUT）、删除（DELETE）接口，仅返回模拟成功响应，不会修改后台原始数据
   - 新增接口返回的 ID 为模拟生成，无法通过 GET 接口查询到对应新增数据
2. 固定数据范围：
   - 商品数据固定 20 条，ID 范围 1~20
   - 购物车数据固定 20 条，ID 范围 1~20
   - 用户数据固定 10 条，ID 范围 1~10
3. 仅做基础参数格式校验，无复杂业务逻辑校验

## 五、测试场景参考
基于本 API 可覆盖的典型测试场景：
1. 商品模块：全量查询、单ID查询、新增商品、更新商品、删除商品、边界值（ID越界）、参数类型错误
2. 购物车模块：全量查询、单ID查询、新增购物车、更新购物车商品、删除购物车
3. 用户模块：全量查询、单ID查询、新增用户、更新用户信息、删除用户
4. 认证模块：正常登录、用户名/密码错误、参数缺失
